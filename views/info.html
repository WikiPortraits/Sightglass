{{head}} About the Tools - Wikimedia Sightglass {{header}}

Wikimedia Sightglass helps you explore Wikimedia's mediacounts dataset, which tracks how often Wikimedia Commons files are loaded. Queries can be run on individual files or category trees. Queries run serverside and the results may be saved by users for later reference and sharing.

Background

Commons contributors often want to know how many views their media receives, and for GLAM institutions it's one of the main ways to measure impact.

The community measures media views in two ways: by the view stats for pages a file appears on and/or by how often the files themselves are loaded. Each approach has trade-offs.

For counting article pageviews: Tools like GLAMorgan surface this data, but only for current usage. Once a file is removed from a page, that past usage drops out of later queries. Other tools such as Commons Impact Metrics store pageview data over time, but this requires opt-in setup and can still miss short bursts (e.g. a file is added to the Wikipedia front page for a day and receives millions of views).

For counting media file loads: The Wikimedia Foundation provides mediacount stats, which track how often individual files are loaded over time. These counts can be inflated by bots, scrapers, and browser preloading, but they capture historic usage and short-lived bursts, so they can paint a fuller picture for impact analysis.

Sightglass was made to help Wikimedia users query and share mediacount stats. Especially when used alongside article usage and pageview data, this helps give a comprehensive picture of media impact.

How Mediacount Data Works

The mediacounts dataset records how often Commons files are transferred to users. Bots, scrapers, and browser prefetching can inflate the numbers; the Wikimedia Foundation filters out much of this traffic, but some still gets through.

For more detail, see the Wikitech documentation.

Limits

Mediacounts data starts on January 1, 2015. The most recent day or two may not be available yet, since the dataset lags slightly behind.

Category queries cover at most 300,000 files, including subcategories. This cap may be raised in the future on request.
